TRIFOLD

Integração de Status de Unidades

Documento técnico para sincronização via Webhook HTTP

Versão: 1.0 Data: 17/06/2026 Protocolo: Webhook HMAC-SHA256 Direção: Sistema externo → Trifold CRM

1. Objetivo

Este documento descreve a integração entre o sistema externo de gestão de unidades e o Trifold CRM. O objetivo é manter o status das unidades (disponível, reservada, vendida) sincronizado em tempo real: quando uma unidade muda de status no sistema externo, o Trifold é notificado automaticamente via webhook HTTP.

Direção do fluxo: Sistema externo → Trifold CRM.
O Trifold não consulta o sistema externo periodicamente — ele aguarda ser notificado.

2. O que o sistema externo precisa fazer

Sempre que o status de uma unidade mudar, o sistema externo deve enviar uma requisição HTTP:

CampoValor
MétodoPOST
URLhttps://crm.trifold.eng.br/api/webhooks/imoveis-sync
Content-Typeapplication/json
Header de autenticaçãoX-Signature-256: sha256=<assinatura>

Corpo da requisição (JSON)

{
  "event": "unit.status_changed",
  "timestamp": "2026-06-17T15:00:00Z",
  "data": {
    "unit_code": "301",
    "property_slug": "vind-residence",
    "status": "vendido",
    "changed_at": "2026-06-17T14:58:00Z"
  }
}

Descrição dos campos

CampoTipoObrigatórioDescrição
event string Sim Sempre "unit.status_changed"
timestamp ISO 8601 Sim Momento em que o webhook foi gerado
data.unit_code string Sim Código/identificador da unidade (ex: "301", "102-A")
data.property_slug string Sim Slug do empreendimento no Trifold (ver Seção 5)
data.status string Sim Novo status da unidade (ver Seção 4)
data.changed_at ISO 8601 Não Momento real da mudança (se diferente do envio)

3. Autenticação — HMAC-SHA256

Cada requisição deve incluir uma assinatura digital no header X-Signature-256. Isso garante que apenas o sistema autorizado pode enviar notificações.

O secret será compartilhado separadamente por canal seguro (não incluso neste documento). Nunca transmita o secret por e-mail ou chat aberto.

Como calcular a assinatura

A assinatura é um HMAC-SHA256 do corpo bruto (raw body) da requisição, usando o secret compartilhado:

# Pseudocódigo
assinatura = HMAC_SHA256(secret, raw_body_string)
header = "X-Signature-256: sha256=" + hex(assinatura)

Exemplos por linguagem

Node.js / JavaScript:

const crypto = require('crypto')

const secret = process.env.TRIFOLD_WEBHOOK_SECRET
const body = JSON.stringify(payload)

const signature = crypto
  .createHmac('sha256', secret)
  .update(body)
  .digest('hex')

fetch('https://crm.trifold.eng.br/api/webhooks/imoveis-sync', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-Signature-256': `sha256=${signature}`,
  },
  body: body,
})

Python:

import hmac, hashlib, json, os, requests

secret = os.environ['TRIFOLD_WEBHOOK_SECRET'].encode()
body = json.dumps(payload).encode()

signature = hmac.new(secret, body, hashlib.sha256).hexdigest()

requests.post(
    'https://crm.trifold.eng.br/api/webhooks/imoveis-sync',
    headers={
        'Content-Type': 'application/json',
        'X-Signature-256': f'sha256={signature}',
    },
    data=body,
)

PHP:

$secret = getenv('TRIFOLD_WEBHOOK_SECRET');
$body   = json_encode($payload);
$sig    = 'sha256=' . hash_hmac('sha256', $body, $secret);

$ch = curl_init('https://crm.trifold.eng.br/api/webhooks/imoveis-sync');
curl_setopt_array($ch, [
    CURLOPT_POST           => true,
    CURLOPT_POSTFIELDS     => $body,
    CURLOPT_HTTPHEADER     => [
        'Content-Type: application/json',
        "X-Signature-256: $sig",
    ],
    CURLOPT_RETURNTRANSFER => true,
]);
curl_exec($ch);

5. Slugs dos Empreendimentos

O campo data.property_slug deve corresponder ao identificador do empreendimento no Trifold:

EmpreendimentoSlug a usarStatus atual

Se um novo empreendimento for adicionado no futuro, o Trifold informará o slug correspondente.

6. Respostas HTTP

CódigoSituaçãoAção recomendada
200 Webhook recebido e processado com sucesso Nenhuma — operação concluída
400 JSON inválido no corpo da requisição Verificar serialização do payload
401 Assinatura inválida ou ausente Verificar o secret e o cálculo do HMAC
404 Empreendimento ou unidade não encontrada Verificar property_slug e unit_code
422 Campos obrigatórios ausentes ou status inválido Verificar payload conforme Seção 2
500 Erro interno no Trifold Reenviar após 60 segundos (retry)

Retry recomendado: Em caso de erro 5xx ou timeout, o sistema externo deve tentar reenviar com backoff exponencial: 1min → 5min → 15min → 30min. Após 4 tentativas sem sucesso, notificar manualmente.

7. Checklist — Para o sistema externo implementar

  • Armazenar o secret em variável de ambiente (nunca hardcoded no código)
  • Implementar o cálculo HMAC-SHA256 conforme Seção 3
  • Enviar o header X-Signature-256: sha256=<assinatura> em toda requisição
  • Usar o slug correto do empreendimento (Seção 5)
  • Mapear os status do seu sistema para os valores da Seção 4
  • Implementar retry com backoff exponencial para erros 5xx
  • Testar com o endpoint de teste (Seção 8) antes de ativar em produção

8. Como Testar

Use o comando curl abaixo para verificar se a integração está funcionando. Substitua SEU_SECRET pelo secret fornecido separadamente:

# Gerar assinatura (terminal Linux/Mac)
BODY='{"event":"unit.status_changed","timestamp":"2026-06-17T12:00:00Z","data":{"unit_code":"301","property_slug":"vind-residence","status":"reservado","changed_at":"2026-06-17T12:00:00Z"}}'
SECRET="SEU_SECRET"
SIG="sha256=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')"

# Enviar webhook
curl -X POST https://crm.trifold.eng.br/api/webhooks/imoveis-sync \
  -H "Content-Type: application/json" \
  -H "X-Signature-256: $SIG" \
  -d "$BODY"

Resposta esperada (sucesso):

{
  "received": true,
  "property": "vind-residence",
  "unit": "301",
  "status": "reserved",
  "available_units": 47
}

10. Observações de Segurança

Não expor o secret: O webhook secret não deve aparecer em logs, commits, issues do GitHub, e-mails ou qualquer canal não criptografado. Compartilhá-lo exclusivamente via mensagem privada ou gerenciador de senhas.

O endpoint é somente-escrita: O webhook apenas atualiza status de unidades. Nenhum dado sensível do Trifold (leads, clientes, dados financeiros) é exposto nesta integração.

Validação timing-safe: A verificação da assinatura usa comparação resistente a timing attacks, impedindo ataques de força bruta por análise de tempo de resposta.
