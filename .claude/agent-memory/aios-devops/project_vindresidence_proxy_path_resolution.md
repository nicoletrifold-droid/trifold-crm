`trifold.eng.br/vindresidence` serve a landing do Vind (projeto Vercel separado `vind-residence`, `prj_bSyrklkya14GAfeXdOlUXdyntqWp`, alias publico `vind-residence.vercel.app`) via **rewrite-proxy** no `vercel.json` do projeto institucional `trifold-design-system` (`prj_1SRBOXwTclTFwGDz3zjIO6uM0pMG`). O proxy NAO duplica arquivos — so acrescenta config. Receita completa (as 4 partes sao TODAS necessarias):

**Rename teste→prod (2026-08-24):** o projeto/dominio foi renomeado de `vind-residence-teste` para `vind-residence` (endereco publico limpo). GOTCHA critico do SSO: o projeto Vind tem `ssoProtection: "all_except_custom_domains"`, que so isenta do login SSO o alias que casa com o **nome do projeto** OU dominios registrados em `/domains` do projeto. Um `vercel alias set ... vind-residence.vercel.app` (alias de deployment) NAO basta — cai no SSO (302 → vercel.com/login). Fix que funcionou: (1) `PATCH /v9/projects/{id}` `{"name":"vind-residence"}`; (2) `POST /v10/projects/{id}/domains` `{"name":"vind-residence.vercel.app"}` (vira domain do projeto, verified=True, isento de SSO → 200 publico); (3) redeploy; (4) remover o domain antigo com `DELETE /v9/projects/{id}/domains/vind-residence-teste.vercel.app` (fica 404). Renomear projeto por si so NAO reatribui aliases nem isenta do SSO — o passo do `/domains` e o que resolve. PRs #499 (index.html+lead.js) e — para versionar o vercel.json do proxy — **#501 (MERGED 2026-08-24)**, que registrou `landing-pages/trifold-design-system/vercel.json` com a receita completa do proxy. (O PR #471 original foi fechado sem mergear; ver [[vercel-landing-pages-projects]].)

1. **redirect trailing-slash:** `{"source":"/vindresidence","destination":"/vindresidence/","permanent":false}`. Sem a barra final, os assets RELATIVOS da landing (`assets/foo.webp`) resolvem contra `/` → `trifold.eng.br/assets/...` → 404. Com barra, resolvem contra `/vindresidence/` → proxied.
2. **rewrites:** `/vindresidence/` → `https://vind-residence.vercel.app/` E `/vindresidence/:path*` → `.../:path*`. Precisa das DUAS: `:path*` NAO casa o path vazio (`/vindresidence/` sozinho), entao a entrada exata da barra e obrigatoria. Mesmo gotcha vale pros headers.
3. **CSP escopada:** o form faz `fetch` cross-origin pro projeto Vind, e a landing usa Google Fonts + thumbnails/embeds YouTube + iframe Google Maps. A CSP site-wide do institucional (`connect-src 'self'`, `font-src 'self'`) MATA tudo isso. Solucao: header rule especifica pra `/vindresidence`, `/vindresidence/` E `/vindresidence/:path*` (3 entradas, mesmo motivo do item 2) com CSP relaxada: `connect-src 'self' https://vind-residence.vercel.app; style-src ... https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://img.youtube.com; frame-src https://www.youtube.com https://www.google.com`. E trocar o source da regra site-wide de `/(.*)` para **`/((?!vindresidence).*)`** (negative-lookahead) — senao o `/(.*)` sobrescreve a CSP escopada (quando 2 header rules setam a mesma key, a ULTIMA que casa no array vence, e `/(.*)` fica por ultimo). As demais 8 paginas mantem CSP/headers byte-identicos.
4. **endpoint absoluto na landing:** `CONFIG.leadEndpoint` no `index.html` do Vind DEVE ser a URL absoluta completa `https://vind-residence.vercel.app/api/lead`, NAO `/api/lead`. Caminho absoluto-de-raiz resolve pra `trifold.eng.br/api/lead` (404, nao passa pelo rewrite). Cross-origin funciona pq `api/lead.js` tem `trifold.eng.br`+`www.` na allowlist de CORS (PR #483). Valor hardcoded: se o projeto/dominio do proxy mudar, atualizar aqui (PR #494).

**Validacao (SSO nos previews):** `trifold-design-system` tem `ssoProtection: all_except_custom_domains` — todo preview `.vercel.app` exige header `x-vercel-protection-bypass`; custom domains (trifold.eng.br) sao isentos. Gerar: `PATCH /v1/projects/{id}/protection-bypass` body `{"generate":{}}` (pega a key com `scope==automation-bypass`); revogar no fim: `{"revoke":{"secret":"...","regenerate":false}}`. `vercel promote` de um preview NAO promove direto (pede rebuild interativo); pra site estatico "framework None" o `vercel deploy --prod` da staging e deterministico (sem build step) e equivalente. Form e2e: POST com `Origin: https://trifold.eng.br` → 200 `{"status":"ok"}` = lead criado (webhook sincrono pos-PR#473), verificar/limpar via Management API.
